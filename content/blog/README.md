# content/blog —— 公司动态的内容源

这个目录是 `/blog` 下所有页面的**唯一真源**：

| 产物 | 从哪来 |
| --- | --- |
| `blog/index.html` | 列表页，由本目录所有 `.md` 的元信息生成 |
| `blog/<slug>/index.html` | 每篇的详情页，正文来自对应的 `.md` |
| 每一页顶部的**跑马灯** | 取最新 8 篇的 `title`（见 `tools/announce.py`） |

也就是说改一个 `title:` 会同时改到三处：列表页卡片、详情页 `<h1>`、以及**全站每一页**
顶部的公告条。公告条的条目不必在这里维护，它自己会跟上。

改了这里的内容，重跑一次即可：

```bash
python3 tools/build_blog.py
```

**不要直接编辑 `blog/` 下的 HTML** —— 那是产物，下次生成会被整个覆盖。

## 一篇文章 = 一个 Markdown 文件

文件名就是 URL：`2026-03-27-aliyun-ppu.md` → `/blog/2026-03-27-aliyun-ppu/`。
改名等于改 URL。

每个文件以 frontmatter 开头：

```markdown
---
title: 破晓石完成阿里云PPU适配           # 详情页 h1 与列表页卡片标题
slug: 2026-03-27-aliyun-ppu             # 必须与文件名一致，生成器会核对
date: 2026-03-27                        # YYYY-MM-DD，决定排序与页面上的日期
cover: assets/img/news/20260327.webp    # 站点根相对路径，文件必须真实存在
tag: 算力适配                            # 列表页「日期 • 分类」的第二个槽位
summary: 成都，2026 年 3 月 27 日 —— …   # 详情页首屏的导语，也用作 meta description
---

正文 Markdown…
```

六个字段**缺一不可**，缺了生成器当场报错退出。它不会猜默认值 —— 猜出来的日期会
安静地把文章排到列表的错误位置。

`cover` 指向的文件不存在也会报错（那会是一张裂图，且只在浏览器里才看得出来）。

## 正文写法

支持的是 Markdown 的一个**子集**，实现在 `tools/mdrender.py`，不依赖任何第三方库。

| 写法 | 结果 |
| --- | --- |
| `## 标题` / `### 标题` | `<h2>` / `<h3>` |
| 空行分段 | `<p>` |
| `- 项` 或 `1. 项` | `<ul>` / `<ol>` |
| `**粗体**` | `<strong>` |
| `*斜体*` | `<em>` |
| `` `代码` `` | `<code>` |
| `[文字](链接)` | `<a>`（站外链接自动加 `target="_blank"`） |
| `![说明](图片)` 单独成一行 | `<figure><img>` |
| `> 引用` | `<blockquote>` |
| `---` | `<hr>` |
| 表格（见下） | `<table>` |
| 以 `<` 开头的行 | 原样透传的 HTML 块 |

**不支持**：嵌套列表、列表项里的多段落、脚注、任务列表、setext 式标题。
遇到不认识的语法会当普通文本输出 —— 宁可原样呈现，也不要错误解析出一段看不懂的
结构。

### 表格

```markdown
| 参数 | 平头哥 PPU | NVIDIA A800 |
|---|---|---|
| 显存容量 | 96GB HBM2e | 80GB HBM2e |
```

### 那张「图片 + 粗体说明」的网格表

`2026-03-27-aliyun-ppu.md` 里有一张产品截图网格，它用**一行空表头**占位：

```markdown
|  |  |
|---|---|
| ![](assets/img/news/20260327-1.webp)<br>**Boss资源识别PPU设备** | … |
```

Markdown 语法强制第一行必须是表头，所以那一行空的必须写；渲染器认得「表头全空」
就不会生成 `<thead>`，产物里是一张没有表头行的干净网格。

单元格里的 `<br>` 用来把图和说明分成两行 —— Markdown 表格单元格里只有行内元素，
不写 `<br>` 它们会挤在同一行。

## 图片

统一放在 `assets/img/news/`。frontmatter 与正文里都写**站点根相对**路径：

```markdown
![说明](assets/img/news/20260327-1.webp)
```

即 `assets/…`，**不要**手写 `../` 前缀。产物有两层深度，前缀由生成器按需加：

| 页面 | 深度 | 实际前缀 |
| --- | --- | --- |
| `blog/index.html` | 1 | `../assets/` |
| `blog/<slug>/index.html` | 2 | `../../assets/` |

自己写错一层就是 404，且只有浏览器里才看得出来。`tools/qa/links.py` 会把这类
路径错误直接报出来。

## 新增一篇

1. 封面与配图放进 `assets/img/news/`（命名跟着日期走，如 `20260601.webp`）
2. 在 `content/blog/` 新建 `<slug>.md`，填好那六个字段
3. `python3 tools/build_blog.py`
4. `python3 tools/qa/links.py` 确认站内链接都通

列表页按 `date` 自动排序，不用手工维护顺序。每篇详情页底部「继续阅读」会自动
取除自己之外最新的两篇。

## 第一份内容是怎么来的

2026-09-11 之前，`/blog` 只是个列表页，每张卡片都跳到线上 poxiaoshi.cn。这个站点
的目标之一是**替换** poxiaoshi.cn，所以内容搬到了本地。

搬家脚本是 `tools/import_posts.py`：它抓线上详情页、抽正文、转 Markdown，并做一次
**往返自检**才肯写盘 —— 源 HTML 与「渲染回来的 HTML」必须纯文本逐字相同、且各标签
计数一致（扣除两处设计内的换算）。对不上就报错，不写文件。

那个脚本**只跑一次**：已存在的 md 一律拒绝覆盖，免得把这里后来的编辑冲掉。留着它
是为了 provenance —— 任何人可以重跑，核对这里的文本与线上原文的对应关系。

搬过来时做了两处编辑，都写在脚本注释里：

* 线上好几篇把封面图在正文开头又放了一张（hero 一张 + 正文一张），本站版式里封面
  由 `.tf-blog-detail-image` 单独呈现，正文那张去掉了
* `tag` 字段线上没有，是按标题补的（算力适配 / 兼容认证 / 行业合作 / 项目交付 /
  生态计划），每个词都能从标题直接读出来

### slug 与日期为什么可能对不上

`slug` 沿用线上路径（如 `2024-12-15-hygon`），这样将来替换站点时 URL 不变，外链与
搜索引擎索引都不会断。

有两条的 slug 日期与 `date` 字段不一致：`2024-12-15-hygon` 实际发布于 2025-12-24，
`2025-10-12-paizi` 实际发布于 2025-09-15。线上本来就是这样（slug 是建档时随手写的）。
`date` 以正文里写的日期为准，列表页显示的也是它；slug 保留原样是为了 URL 稳定。
